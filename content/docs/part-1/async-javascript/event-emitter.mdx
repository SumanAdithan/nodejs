> **Source:** `1. node-tutorial/10. event-emitter`

Node is **event-driven**. Much of its core (HTTP servers, streams, sockets) is built on `EventEmitter` from the built-in `events` module.

| Method                    | Meaning                                    |
| ------------------------- | ------------------------------------------ |
| `emitter.on(name, fn)`    | Register a listener for an event           |
| `emitter.emit(name, ...args)` | Fire the event, passing args to listeners |

## Basic emitter

```js title="index.js"
const EventEmitter = require("events");

const myFirstEmitter = new EventEmitter();

// register a listener
myFirstEmitter.on("greet", (name) => {
  console.log(`Hello ${name}`);
});

myFirstEmitter.emit("greet", "Sangam Mukherjee"); // Hello Sangam Mukherjee
```

<Callout>Register listeners **before** emitting. Events emitted with no listener are just lost.</Callout>

## Custom emitter (extending the class)

```js title="custom-listener.js"
const EventEmitter = require("events");

class MyCustomEmitter extends EventEmitter {
  constructor() {
    super();
    this.greeting = "Hello";
  }

  greet(name) {
    this.emit("greeting", `${this.greeting}, ${name}`);
  }
}

const myCustomEmitter = new MyCustomEmitter();

myCustomEmitter.on("greeting", (input) => {
  console.log(`Greeting event`, input);
});

myCustomEmitter.greet("Sangam Mukherjee"); // Greeting event Hello, Sangam Mukherjee
```

## Quick recap

- `const EventEmitter = require("events")`
- Listen with `.on()` and fire with `.emit()`.
- Extend `EventEmitter` to make classes that emit their own events. Socket.IO uses the same `on`/`emit` style.
